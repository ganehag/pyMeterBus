# pyMeterBus 2.0.0a2 release notes

`2.0.0a2` is the second v2 prerelease. It keeps the v2 decoder API shape from `2.0.0a1` and focuses on release-readiness, packaging validation, documentation, and GitHub Actions publishing safety.

This is still a prerelease. It is suitable for TestPyPI rehearsal and external feedback, but it is not the final `2.0.0` stability contract.

## What changed since 2.0.0a1

- The v2 test gate now runs the full `tests` directory instead of a hand-picked subset.
- Stale packaging, export-view, release-note, and workflow tests were updated to match the v2 package policy.
- The package remains dependency-free by default and has no optional legacy dependency groups.
- A v1-to-v2 migration guide was added and linked from the README.
- Diagnostics and decode-mode documentation was added and linked from the README.
- Release workflow behavior is now covered by tests.
- Production PyPI publishing is manual-only and guarded by an `origin/master` containment check.
- TestPyPI publishing remains tag-driven for non-master prerelease rehearsal.
- GitHub Actions were updated to the current documented major versions:
  - `actions/checkout@v6`
  - `actions/setup-python@v6`
  - `actions/upload-artifact@v7`
  - `actions/download-artifact@v8`
  - `pypa/gh-action-pypi-publish@release/v1`
- No Dependabot configuration was added.

## Breaking changes

The breaking-change policy is unchanged from `2.0.0a1`:

- v2 is not a drop-in replacement for the legacy object model.
- The package root is intentionally lightweight and v2-focused.
- `import meterbus` exports only the small v2 decode surface: `decode`, `decode_one`, and `decode_one_frame`.
- Legacy classes, serial helpers, wireless telegram classes, and `meterbus.load()` are not part of the v2 root API.
- The default install has no runtime dependencies.
- Stale optional dependency groups and serial console entry points remain removed.
- Serial transport is caller-owned: read complete frame bytes in your application, then pass them to `decode()`.
- Supported Python metadata targets Python 3.11, Python 3.12, and Python 3.13.

## Supported public API

Preferred imports:

```python
from meterbus import decode
from meterbus.api import decode
from meterbus.export import to_dict, to_json
from meterbus.model import DecodeMode
```

The package root exports:

```python
from meterbus import decode, decode_one, decode_one_frame
```

`decode()` returns a structured `DecodeResult` with an `ok` flag, decoded frame or telegram data, diagnostics, and the original raw bytes.

## CLI

From a checkout:

```shell
python -m meterbus.cli.decode "E5"
```

After installing the wheel:

```shell
pymeterbus-decode "E5"
pymeterbus-decode --indent 2 "E5"
pymeterbus-decode --mode lenient "10 40 0B 00 16"
```

Exit codes:

- `0`: decode completed and `DecodeResult.ok` is true.
- `1`: decode completed and `DecodeResult.ok` is false, or compact expansion produced an error diagnostic.
- `2`: invalid CLI input, such as malformed hex.

## Install and packaging

The default install is intentionally dependency-free:

```shell
python -m pip install pymeterbus==2.0.0a2
```

Supported Python versions for v2 metadata and CI are:

- Python 3.11
- Python 3.12
- Python 3.13

The v2 build smoke test verifies that a clean wheel install can run `pymeterbus-decode "E5"` without installing optional runtime dependencies.

## Implemented decoder coverage

Decoder coverage is unchanged in scope from `2.0.0a1`:

- ACK, short, control, and long frame decoding.
- Strict, lenient, and compat decode modes.
- Checksum and frame diagnostics.
- Variable-data telegram header decoding for CI `0x72` and CI `0x76`.
- Fixed-data telegram decoding.
- DIF/DIFE parsing.
- Base VIF/VIFE parsing and selected extension VIF/VIFE handling.
- Fixed-length values.
- Variable-length text and BCD values.
- Integer, BCD, float, date, time, and datetime value handling for implemented formats.
- Single data record decoding.
- Telegram record loop.
- Record-level VIF scaling.
- Unknown record preservation in lenient and compat modes.
- Format-frame descriptor parsing.
- Explicit compact-frame expansion from caller-supplied descriptors or a format telegram.
- Compact Format Signature validation.
- Compact Full-Frame-CRC validation over recovered application data.
- `to_dict()` export.
- `to_json()` export.
- Full, summary, and records export views.

## Known gaps

- More real-world manufacturer fixtures are needed.
- Extension VIF table coverage is incomplete.
- Unsupported or enhanced VIF representation may still change.
- More date/time and variable-length value examples are needed.
- DIF/DIFE storage, tariff, and subunit behavior needs more validation against real telegrams.
- Compact/format support currently has synthetic tests and spec-shaped behavior; real captures should be added when available.
- v2 model stability is still preview-level.
